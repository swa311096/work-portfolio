# SPL Metrics To Track

Metric library and dashboard guide for project proposals, ramp plans, quality systems, and economics.

Purpose: this page gives a reusable metrics library for any SPL-style interview case. It is intentionally broad, but in a timed case the final answer should select only the 12-18 metrics most relevant to the prompt. The memo should stay concise; the spreadsheet should carry the metrics, formulas, assumptions, and tracking plan.

## How To Use This In A Two-Hour Case

| Action | What to do |
|---|---|
| Step 1: Pick the North Star | Choose one primary success metric tied to the client objective, such as accepted records delivered, verified experts onboarded, resolution quality, or gross margin. |
| Step 2: Select 4-6 metric categories | Use only the categories that matter for the case: sourcing, vetting, production, quality, delivery, economics, client alignment, or risk. |
| Step 3: Build a simple dashboard | Create one Excel tab with current target, weekly target, owner, and risk status. Do not overbuild. |
| Step 4: Add formulas below the dashboard | Use clear formulas for acceptance rate, rework rate, throughput, utilization, margin, and on-time delivery. |
| Step 5: Mention metrics briefly in the memo | The memo should reference the tracking system at a high level and point to the Excel model for detail. |

## Metric Selection Rule

Do not track every metric in the final deliverable. Use this library as a menu. In a timed interview, the strongest approach is to show 10-15 metrics that map directly to the client goal, delivery plan, quality controls, and economics.

## A. KPI Stack For Any SPL Project

| Metric layer | What it measures | Why it matters | Examples |
|---|---|---|---|
| North Star | Primary project outcome | Defines whether the pilot succeeded | Accepted outputs delivered on time; validated expert bench; production-ready dataset; client-approved launch |
| Input Metrics | Early indicators of future output | Shows whether the team is building enough capacity | Candidates sourced; experts screened; experts onboarded; tasks assigned |
| Process Metrics | How work moves through the system | Identifies bottlenecks before delivery slips | Cycle time; throughput; utilization; review queue age |
| Quality Metrics | Whether output is usable | Protects the client and avoids rework | Acceptance rate; defect rate; reviewer disagreement; final audit pass rate |
| Delivery Metrics | Whether milestones are met | Tracks schedule health | On-time delivery; cumulative output vs. plan; SLA adherence |
| Economic Metrics | Whether the project is profitable | Shows business ownership | Cost per accepted output; gross margin; billable utilization; rework cost |
| Client Metrics | Whether the client trusts the project | Critical for renewal and expansion | Calibration sign-off; feedback turnaround; open issues; expansion readiness |

## B. Scope, Setup, And Planning Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Scope clarity score | Qualitative score from 1-5 on whether deliverables, acceptance criteria, and client decisions are clearly defined. | Use during kickoff; target 4+ before scale. |
| Assumption coverage | Number of key assumptions documented / total assumptions needed. | Useful for ambiguous cases; target 100% of material assumptions documented. |
| Acceptance criteria completeness | Accepted criteria fields completed / required criteria fields. | Target 100% before production. |
| Workflow taxonomy completion | Workflows defined / workflows planned. | Target 100% before production ramp. |
| Template readiness | Templates approved / templates required. | Target 100% before work begins. |
| Pilot milestone coverage | Milestones defined / milestones required. | Target: kickoff, calibration, ramp, delivery, final audit. |
| Open decision count | Number of unresolved client or internal decisions blocking production. | Track weekly; should decrease over time. |
| Setup cycle time | Days from approval to first production-ready task. | Shows startup speed; target depends on case. |

## C. Expert Sourcing And Recruiting Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Candidates sourced | Total prospective experts identified. | Input metric for ramp sufficiency. |
| Source mix | Share of candidates by channel: LinkedIn, referrals, communities, agencies, job boards. | Helps identify scalable sourcing channels. |
| Outreach response rate | Responses / outreach messages sent. | Measures sourcing efficiency. |
| Qualified lead rate | Qualified candidates / total candidates sourced. | Shows quality of sourcing. |
| Screen pass rate | Candidates passing resume/profile screen / candidates screened. | Measures top-of-funnel fit. |
| Interview pass rate | Candidates passing interview / candidates interviewed. | Measures vetting rigor. |
| Work sample pass rate | Candidates passing work sample / candidates tested. | Best indicator of production readiness. |
| Offer acceptance rate | Experts accepting role / offers extended. | Measures competitiveness of pay and project pitch. |
| Time to onboard expert | Days from first outreach to production-ready status. | Important for ramp feasibility. |
| Bench coverage ratio | Available qualified experts / experts needed at peak. | Target >1.2x to protect against attrition. |

## D. Expert Vetting, Training, And Calibration Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Credential verification rate | Verified experts / experts requiring verification. | Used for regulated or technical domains. |
| Training completion rate | Experts completing onboarding / experts onboarded. | Target near 100% before production. |
| Calibration pass rate | Experts passing calibration / experts attempting calibration. | Determines who can enter production. |
| Calibration score | Average expert score on gold-standard examples. | Useful for tiering experts. |
| Time to productivity | Days from onboarding to first accepted output. | Measures training efficiency. |
| Tier distribution | Experts by role or quality tier: creator, reviewer, senior reviewer. | Shows staffing mix and review capacity. |
| Expert utilization | Actual expert hours / available expert hours. | Target balanced utilization; too high creates quality risk. |
| Expert activation rate | Experts completing at least one accepted task / onboarded experts. | Measures usable bench size. |
| Expert attrition rate | Experts inactive or dropped / total active experts. | Track weekly; high attrition threatens ramp. |
| Expert NPS / satisfaction | Survey score or qualitative feedback from experts. | Optional; helpful for long projects. |

## E. Production Throughput Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Tasks assigned | Number of tasks assigned to creators or operators. | Leading indicator of output. |
| Tasks submitted | Number of tasks submitted for review. | Tracks production progress. |
| Accepted outputs | Number of outputs that pass review and are delivery-ready. | Core production output metric. |
| Cumulative output vs. plan | Cumulative accepted outputs / planned cumulative accepted outputs. | Core schedule health metric. |
| Weekly throughput | Accepted outputs per week. | Tracks ramp and scale. |
| Throughput per expert | Accepted outputs / active experts. | Shows productivity by bench size. |
| Hours per accepted output | Total expert hours / accepted outputs. | Critical for economics and staffing. |
| Cycle time | Time from task assignment to accepted output. | Measures process speed. |
| Review queue age | Average age of tasks waiting for review. | Identifies review bottlenecks. |
| Bottleneck stage | Stage with the longest average queue time. | Useful for diagnosing delays. |

## F. Quality And Acceptance Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Acceptance rate | Accepted outputs / submitted outputs. | Core quality metric; should improve after calibration. |
| First-pass acceptance rate | Outputs accepted without rework / submitted outputs. | Measures creator quality. |
| Rework rate | Outputs requiring revision / submitted outputs. | Measures avoidable quality cost. |
| Rework cycles per output | Total rework rounds / outputs requiring rework. | High values indicate unclear instructions or weak experts. |
| Final audit defect rate | Defects found in audit / audited accepted outputs. | Final quality guardrail. |
| Critical defect rate | Critical defects / audited outputs. | Use for safety, legal, compliance, or factual issues. |
| Rubric completeness rate | Records with all required rubric fields / total records. | For evaluation-data cases. |
| Source consistency rate | Records correctly grounded in approved sources / audited records. | Useful for technical or policy domains. |
| Duplicate rate | Duplicate or near-duplicate outputs / total outputs. | Protects dataset diversity. |
| Difficulty mix adherence | Actual difficulty distribution / planned difficulty distribution. | Ensures dataset is not too easy or too hard. |

## G. Review, Calibration, And Adjudication Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Review coverage | Reviewed outputs / total submitted outputs. | Target 100% for high-stakes deliverables. |
| Double-review coverage | Double-reviewed outputs / total outputs. | Usually 10-25% depending on risk. |
| Reviewer agreement rate | Reviews with same pass/fail or similar score / double-reviewed outputs. | Measures consistency. |
| Reviewer disagreement rate | Disagreements / double-reviewed outputs. | High disagreement signals ambiguous standards. |
| Adjudication rate | Outputs requiring senior review / reviewed outputs. | Shows complexity or reviewer uncertainty. |
| Reviewer throughput | Reviewed outputs / reviewer / week. | Tracks review capacity. |
| Reviewer turnaround time | Time from submission to review decision. | Important for avoiding bottlenecks. |
| Gold set drift | Change in expert performance on repeated gold examples over time. | Useful in longer projects. |
| Calibration meeting action closure | Actions closed / actions created during calibration. | Ensures feedback turns into process changes. |
| Instruction-change frequency | Number of guideline updates per week. | High number may mean scope is unstable. |

## H. Delivery And SLA Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| On-time milestone rate | Milestones delivered on time / total milestones. | Core delivery reliability metric. |
| Weekly plan attainment | Actual weekly accepted output / planned weekly accepted output. | Useful for ramp tracking. |
| Delivery completeness | Delivered accepted outputs / contracted accepted outputs. | Client-facing fulfillment metric. |
| SLA adherence | Tasks completed within SLA / total tasks subject to SLA. | Use when timeline guarantees exist. |
| Schedule variance | Actual completion date minus planned completion date. | Track in days. |
| Buffer consumption | Contingency days used / total contingency days. | Shows schedule risk. |
| Backlog size | Open tasks not yet accepted. | Monitor against remaining capacity. |
| Ready-to-deliver count | Accepted outputs awaiting delivery packaging. | Ensures production is not confused with delivery. |

## J. Financial And Commercial Metrics

| Metric | Formula / Definition | How to use / Target |
|---|---|---|
| Client price | Total contracted pilot price. | Top-line revenue for the project. |
| Price per accepted output | Client price / accepted outputs. | Useful for output-based pricing. |

## P. How To Reference Metrics In The Memo

Use one concise paragraph. The memo should not list every metric. It should say that the attached project plan tracks weekly progress across production, quality, expert bench health, client alignment, and economics.

Example language:

> Mercor will manage the pilot through a weekly operating dashboard tracking accepted records, production throughput, acceptance rate, rework rate, reviewer disagreement, active expert capacity, client feedback turnaround, and gross margin. The attached project plan includes the detailed metric definitions, targets, and review cadence.

## Q. Final Checklist Before Submitting

- Is there one clear North Star metric?
- Do the metrics map to the client goal and pilot deliverable?
- Are quality metrics separated from production metrics?
- Does the economics tab connect hours, cost, price, and margin?
- Does the ramp plan show weekly output and staffing assumptions?
- Are risks measurable, not just described qualitatively?
- Does the memo stay concise and point to the spreadsheet for detail?
- Are assumptions clearly labeled when the prompt does not provide numbers?
